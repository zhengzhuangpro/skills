# distill-to-skill

## 指令正文

你的任务：把用户提供的素材提炼成一个**独立自包含**的 skill。产出的 skill 不引用、不依赖任何外部仓库、模板文件或样例文件——所有格式、模板、示例、判断标准全部内置于它自己的 SKILL.md 里，拷到任意电脑、交给任意 AI 助手都能直接用。

### 1. 收集并理解素材

- 素材来源不限：粘贴的文本、文件路径、URL、聊天记录、笔记。
- 通读全部素材后再动手。素材里有含糊或矛盾的地方，先向用户确认，不要猜。

### 2. 提炼（核心步骤）

提炼的是**可复用的方法和判断标准**，不是原文存档：

- 问自己：用户以后遇到什么类似任务时，会希望 AI 按这套方式做？
- 保留：流程步骤、判断依据、取舍原则、检查清单、用户明确的偏好。
- 丢弃：一次性的上下文、具体项目细节、寒暄和过程性内容。
- 如果素材里隐含了用户的工作习惯（比如"先问再做"、"输出要简洁"），把它写成明确指令。

### 3. 命名

- 英文 kebab-case，从内容本质出发（如 `news-to-x-post`、`distill-to-skill`）。
- 任何可复用的方法都可以做成 skill，不受主题限制。

### 4. 生成自包含的 skill

在用户指定的位置创建 `<skill-name>/SKILL.md`（用户未指定就放当前目录）。格式定义直接写进文件里，结构如下：

```
---
name: <skill-name>
description: |
  一句话说明做什么 + 什么时候触发。
  触发词：xxx, yyy, zzz
---

# <skill-name>

## 指令正文

（给 AI 的完整指令：步骤化、祈使句、可直接执行）
```

写作要求：

- frontmatter 的 `description` 写清楚"做什么 + 什么时候触发"，触发词贴近用户平时的说法。
- 指令正文用祈使句、步骤化，每一步可直接执行，不写空话。
- 所需的格式、模板、示例、判断标准**全部写进 SKILL.md 本身**，禁止出现"参见某仓库 / 某文件 / 某链接"。
- 只生成 `<skill-name>/SKILL.md`，不生成 git 操作，不更新任何仓库的 README，不执行任何安装命令。

### 5. 交付

生成后告诉用户三种用法：

1. 把 `<skill-name>/` 目录拷进任意 agent 的 skills 目录（如 `~/.claude/skills/`、`~/.agents/skills/`）即可长期生效。
2. 直接把 SKILL.md 全文粘贴给任意 AI 助手，当次对话立即生效。
3. 整个目录拷到其他电脑，用法同上。
