# News to X Post

## 指令正文

你的任务：把用户粘贴的外部新闻/通报素材，提炼成一篇符合库内既定格式的 X 发布稿，写入 Obsidian 库。

### 1. 读取格式参照

- 找库里最近的已发布样例：`Calendar/已发布帖子/X 发布稿：*.md`（没有就看 `Calendar/文章草稿/`）。
- 同时读库根目录 CLAUDE.md 的"独立开发者日志工作流"一节。
- 格式以样例和 CLAUDE.md 为准，不自行发明结构。

### 2. 确认口吻

素材是第一人称官方通报（"我们……"），而发布载体是用户个人账号时，动笔前先问一个问题，二选一：

- 官方口吻（"我们"，适合官方账号直接发布）
- 观察者日记口吻（转述，"今天看到……"）

素材本来就是第三方新闻、或用户已指定口吻时，不问，直接写。

### 3. 列事实清单

通读素材，把所有可核验要素列出来：机构名、产品名、版本号、数字、审计/检测结论、承诺事项。

写作只允许使用清单内的事实。不补充猜测，不加评价性形容词，不脑补因果。

### 4. 写一条推文 × 三个风格版本

- 朴素日记体：平铺直叙转述全部关键事实，从"今天看到……"起笔
- 复盘分析体：拆成编号要点，点出信息量最大的部分，收在一句话结论上
- 极简数字体：短句 + 冒号，只留数字、机构名和结论，每行一个要素

每条硬约束（写完逐条自查）：

- ≤140 中文字。超了删修饰词，不删事实
- 只陈述事实：不玩梗、不抖机灵、不用网感句
- 文末单独一行只放 `#独立开发者日记`，不加其他 hashtag

### 5. 落盘

路径：`Calendar/文章草稿/X 发布稿：YYYY-MM-DD.md`（文件名用全角冒号"："；日期用用户给的，没给就跑 `date` 查当天）。

结构：

```markdown
---
分类: 独立开发者日志
产品: <素材涉及的产品/主题>
渠道: X
日期: YYYY-MM-DD
tags:
  - 日志/独立开发
  - 发布稿/X
---

# X 发布稿 · YYYY-MM-DD

<一行说明本次发什么、共几条>

## <话题> · 版本一 · 朴素日记体

<正文>

#独立开发者日记

## <话题> · 版本二 · 复盘分析体
...
```

### 6. 收尾

- 回复里给出新文件的 wikilink，并逐条自查结果（字数、事实核对）。
- 提醒用户：发布后把文件移入 `Calendar/已发布帖子/`。
