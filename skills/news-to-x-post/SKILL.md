# News to X Post

## 指令正文

你的任务：把用户提供的外部新闻/通报素材，提炼成一篇格式完整的 X 发布稿。本 skill 自带全部格式定义，直接按下文执行，不需要读取其他仓库、样例文件或 CLAUDE.md。

### 1. 确认口吻

素材是第一人称官方通报（"我们……"），而发布载体是用户个人账号时，动笔前先问一个问题，二选一：

- 官方口吻（"我们"，适合官方账号直接发布）
- 观察者日记口吻（转述，"今天看到……"）

素材本来就是第三方新闻、或用户已指定口吻时，不问，直接写。

### 2. 列事实清单

通读素材，把所有可核验要素列出来：机构名、产品名、版本号、数字、审计/检测结论、承诺事项。

写作只允许使用清单内的事实。不补充猜测，不加评价性形容词，不脑补因果。

### 3. 写一条推文 × 三个风格版本

- 朴素日记体：平铺直叙转述全部关键事实，从"今天看到……"起笔
- 复盘分析体：拆成编号要点，点出信息量最大的部分，收在一句话结论上
- 极简数字体：短句 + 冒号，只留数字、机构名和结论，每行一个要素

每条硬约束（写完逐条自查）：

- ≤140 中文字。超了删修饰词，不删事实
- 只陈述事实：不玩梗、不抖机灵、不用网感句
- 文末单独一行只放 `#独立开发者日记`，不加其他 hashtag

### 4. 落盘

完整文件结构（本 skill 唯一格式来源）：

````markdown
---
分类: 独立开发者日志
产品: <素材涉及的产品/主题>
渠道: X
日期: YYYY-MM-DD
tags:
  - 日志/独立开发
  - 发布稿/X
---

# X 发布稿 · YYYY-MM-DD

<一行说明本次发什么、共几条>

## <话题> · 版本一 · 朴素日记体

<正文>

#独立开发者日记

## <话题> · 版本二 · 复盘分析体

<正文>

#独立开发者日记

## <话题> · 版本三 · 极简数字体

<正文>

#独立开发者日记
````

日期用用户给的，没给就跑 `date` 查当天。文件名 `X 发布稿：YYYY-MM-DD.md`（全角冒号"："）。

输出位置：

- 当前在 knowledge-garden Obsidian 库中：写入 `Calendar/文章草稿/`，并提醒用户发布后移入 `Calendar/已发布帖子/`
- 其他任何环境：写入当前目录；不便落盘时直接在回复中给出全文

### 5. 收尾

- 回复中给出文件路径（库内用 wikilink），附自查结果：每条字数、事实核对情况。
